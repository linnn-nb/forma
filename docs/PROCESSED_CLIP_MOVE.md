# 处理后片段移动（2026-10-15）

本增量将普通、Elastic／Warp 及 Clip FX 来源 Comp 的整体位置移动接回同一 L1 `clip.move`、Grabber 和 Nudge。`movable_audio` 与自由结构编辑 `editable_audio` 分离；修剪、拆分、复制粘贴没有随移动权限一并放行。专项414项/29.38秒通过，最终回归以 P3 证据为准，完整产品尚未验收。

选择片段，用工具栏 Grabber 或 Smart 下半部拖动；逗号／句号或数字键盘减／加执行 Nudge。Shift 多选后 Nudge 使用共同采样位移；所有入口仍可改键。对两侧配对片段提交共同位移（如多选 Nudge）会同时移动交叉淡化；独立移动其中一侧沿用原有解除配对规则，预览显示影响。Cmd Z／Cmd Shift Z 撤销重做，Cmd S 保存，重开保留原事务。鼠标拖动本身的像素位移按捕获的时间轴比例舍入为采样位移，不把两次独立坐标舍入的差当作拖动位移。

L1 只改变原生 Clip 的 start 属性，保留实际存储的 duration、offset、完整 Warp／Elastic／FX 描述、媒体引用和插件实例；不把内部时长先量化成界面显示采样数再写回。处理来源的媒体 SHA 和描述在移动前重新核验，锁定、版本冲突、时间线边界及整组规则仍生效。小节拍显示随新工程位置更新，源坐标不变。

移动不增加新 DSP、引擎、服务或 RT 工作。已经准备的音频仍由原生节点读取，Clip FX 保留完整输入、来源包络与选段窗口。轨道自动化按既有跟随设置处理，不据本轮无复杂曲线的对照声称所有联动组合已通过。

回归发现原生 TrackList 在历史回放后异步执行 sortTracksByType，向 UndoManager 追加未命名排序动作。修复通过既有审计补丁收束排序：提交及历史边界前只刷新原生派生排序，不派发整个消息队列；历史恢复不再次排队排序。17份SDK补丁/38文件已重放核验；原有未知事务保护保留，测试直接检查另一工程重开／渲染期间当前会话的 Undo 描述不变。

`ProcessedMoveTests.cpp` 覆盖六组合：普通／SoundTouch／Warp × 无效果／四原生 Clip FX。验证真实 WAV 位移、配对 ID／来源描述、原 Undo/Redo、保存重开、原生组件合成 Grabber／Nudge、稳定 ID 选择、锁定和过期 Plan。预算沿用 PCM 2e-6、来源5秒、每次 WAV10秒，新增整套180秒；补测100001帧44.1k PCM的显式无历史旧工程分数时长，原生时长在移动、Undo和重开后精确保留。新导入按工程网格对齐与旧工程保存表示分别测试。合成组件事件不代替物理键鼠或监听。
