# 缺失媒体的工程删除

缺失原始音频时，仍可删除完整工程片段；Command Z 恢复原引用、处理描述和插件状态。删除不写入或移除原媒体。保存重开后仍可撤销原始删除。当前范围与实际结果以 [P3证据](../evidence/P3/summary.md) 为准，完整产品尚未完成。

停止播放，在 Edit 选择离线片段，按 Backspace；可在键位设置中自定义。检查器的删除按钮共用相同 L1 命令。完整选中离线片段的时间范围也可以删除；不能在缺失来源上静默生成新的局部音频切片。

打开实际演示工程：本地 `build-v2-tracktion/p3-offline-delete-current-results.json` 中 `offline_delete.cases[].restored_session`。测试原文件完整保存在同目录的 `Parked-original.wav`，原引用仍指向 `Original.wav`，因此演示工程真正处于离线状态。可试 Delete、Undo、Redo、保存重开；要试听恢复后的原音频，将这个测试文件移回原引用路径，先确认目的路径不存在。工程内删除本身不会移动文件。

配对 Comp 删除一个成员会在预览中声明解除交叉淡化配对；同一原生 Undo 恢复成员和原配对 ID。编辑组需要完整成员与完整授权范围，一次事务删除或恢复。原 Take 和未激活 Playlist 的媒体引用继续保留。

| 前置条件 | 行为 | 实现与验证 |
| --- | --- | --- |
| 原文件缺失 | 校验真实对象、所有者、来源、几何的引用指纹及文件存在状态；不伪造媒体 SHA | `ClipReferenceState.h`、`normaliseClipDeletion`；`OfflineDeleteTests.cpp` |
| 原文件存在 | 继续核验实际文件字节 SHA256 | `EngineCommands.cpp`、`ClipCommands.cpp`；错误媒体哈希拒绝 |
| 文件重新出现或引用改变 | 拒绝过期预览，重新规划 | 真实文件移动/恢复、引用指纹与版本冲突测试 |
| 锁定或越出权限 | 整笔拒绝 | `Scope.cpp`、原生锁定/组/actor 规则；只读/目标范围测试 |
| 重试与恢复 | 原回执重放；Undo 后重试返回 undone，不能再次删除 | 原幂等与 UndoManager、冷重开历史测试 |
| 活动时间线删空 | 按显式区间实际渲染静音并核验 WAV；响度交付不冒充通过 | 普通 Renderer 与正式 verified export 两条路径均验 |

`clip.delete` 对实际对象封入 `source_reference_hash`、`source_present`；在线时另有 `media_hash`。同一 Plan 内的局部新对象引用继续使用原先封定的媒体哈希。查询的 `source_reference` 返回已解析文件引用，保存的相对/绝对编码不构成工程语义差异；未解析引用仍保留在原生状态和历史中。引用指纹继续封定实际原生编码，不代表媒体内容或插件状态哈希；工程 revision 与原生参数捕获继续保护完整编辑状态。其它音频编辑仍核验媒体，不因这次删除能力而开放离线复制、拆分或修剪。

文件存在性为查询快照，预览与提交重新检查；本增量没有完整的文件系统监听或媒体重定位面板。已知离线片段显示离线文字，不绘制假波形。空时间线渲染仍经过实际 Tracktion 图、插件和文件验证，仅对没有活动片段的显式导出放开有声节点条件；非空图和分析路径的原检查保持。

无新依赖、SDK 补丁或实时处理。固定预算：来源准备 5 秒、每普通 WAV 10 秒、正式导出 12 秒、专项 180 秒、PCM 误差 2e-6。测试使用自有真实 PCM/WAV 与实际文件缺失，不是测试替身；合成命令键不替代物理键鼠、硬件或听评。不可读但存在的源、损坏工程、复杂关联/第三方状态失败、旧读者/性能与其它差距仍见 [NEXT_STEPS.md](NEXT_STEPS.md)。
