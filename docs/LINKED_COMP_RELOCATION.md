# 关联 Comp 整组跨轨迁移

可以把活动关联 Comp 的全部成员搬到新的音频轨道，同时保留 Comp Set、Playlist、片段和 Take 身份。目标原播放列表会保留为非活动状态，源轨留下空 Playlist；不会自动播放原 Take 填补源轨空缺。接受前须核对这一整组播放切换。

## 操作

1. 停止录放，选择关联 Comp 的一个片段，按 F8 从主体或名称区跨轨拖动。也可按 Command Control Option ↑/↓，快捷键可改。
2. 选择会展开整组的所有片段和 Edit 组闭包。预览列出源、目标、Playlist 切换、目标暂存片段及自动化范围；拒绝则工程不改。
3. 接受后一次 Command Z 撤销，Shift Command Z 重做。保存、关闭、重开后，原操作仍可撤销和重做。
4. 在目标轨的 Playlist 面板执行整组恢复，会恢复目标原播放列表；源轨原 Take 和其它播放列表一直保留在原轨。可再次整组播放 Comp，或撤销恢复。

当前模型的一个关联成员就是一条完整 Playlist，因此不会把其它片段混入搬来的活动 Comp Playlist。目标原素材会暂存；这与普通非关联片段跨轨移动的混合目标行为不同，预览会明确说明。轨道插件、发送、输出、编辑组定义均保留，Comp 进入目标轨道处理链。

## 工程规则

- 一个来源 Playlist 的全部片段必须去同一目标，目标轨道不可合并多个成员。必须完整、活动、未锁定；锁定/冻结/印刻、缺成员、不同位移或目标属于其它未参与关联组时整笔拒绝。
- 支持分离目标、A/B→B/C 这样的相邻重叠和成员交换。L1 先准备空列表、暂存目标素材及转移所有描述符，再用原生 `Clip::moveTo` 迁移实际对象，最后更新活动列表、成员引用、几何清单和交叉淡化。仍是一个原生 UndoManager 事务，不复制删除选中片段。
- 源空列表 ID 由原 Playlist ID 与 revision 导出，进入原生保存和历史。目标 Main 在需要时实际物化；`restore_playlist` 指向目标先前的播放列表，重叠来源使用其空列表。来源原 Take 和媒体不搬走、不覆盖。
- Playlist 的 `origin_track` / `origin_restore_playlist` 保留最初来源；Clip 的 `ndaw_comp_origin_track` 指向 Comp 选段的来源轨道，`ndaw_take_origin_track` 指向 Take 所在来源轨道。新 Take 注册/Loop 捕获记录后者，新 Comp 创建记录前者；复制保留元数据，两种字段分别表示选段和 Take 来源；嵌套 Comp 组合仍待专项。旧片段缺少明确标记时查询返回 `null`，不猜测为当前轨道。
- 看似空的源轨仍可能保留被引用的原 Take。已记录的来源轨道或其文件夹在关联成员仍引用它时不可直接删除，须先明确解除关联；缺失旧来源标记的补全仍待验证。
- 预览的 `linked_comp` 包含成员、来源空列表、目标原列表、暂存片段及状态 hash。版本冲突、幂等和两侧轨道 Scope 沿用统一命令；整条播放列表切换要求完整时间授权，不能只授权片段窗口。目标锁定片段不能被静默转为非活动。
- 自动化复用冻结源曲线的现有迁移，尾随校验排除本次明确转为非活动的目标片段；不会绕过实际仍活动的片段冲突。同一实际采样位移的重叠片段按声明的整数位移合并共享曲线区间，原生分数采样端点仍精确比较，不用 epsilon。已合并区间的成员不再被误判为自己的尾随碰撞。GUI 不直接写 Edit，没有新引擎、SDK、DSP、IPC 或实时任务。

## 验证范围

编号 `P3-LINKED-RELOCATE-01`；代码 `LinkedCompRelocation.cpp`、`ClipRelocation.cpp`、`PlaylistCommands.cpp`、`PlaylistEditing.cpp`、`Scope.cpp`、`ui/WorkspaceGrabber.cpp`；专项 `LinkedRelocationTests.cpp`。

专项使用真实相反极性 PCM24 双声道文件、两轨 Take、四个 Comp 片段和关联交叉淡化。三场景覆盖分离目标加1000采样位移、相邻重叠且有目标原素材、成员交换；检查实际 Clip 指针/ID、Playlist/Take 引用、相位抵消及单麦非零音频、目标素材恢复、原 Undo/Redo 和三工程冷重开。窗口事件通过实际 Workspace 注册键位和异步接受；不是实体键鼠或听评。

预设预算保持：PCM误差2e-6，来源准备5秒、单次真实 WAV 渲染10秒、专项180秒。当前终态和构建/测试证据见 [P3汇总](../evidence/P3/summary.md)。

已补普通、SoundTouch 线性伸缩/变调、非线性 Warp，各自有无四个非默认原生 Clip FX，结合音量/声像 Read 曲线的三种迁移场景。逐帧比较完整 10 秒输出，原生插件 ID、精确 float 参数值、未知状态、原 Undo/Redo 和冷重开保留；XML 十进制写法不同不等于 DSP 值不同，一个 float ULP 的变化仍会被拒绝。此范围不等于所有插件或路由组合。复杂轨道 FX/PDC/路由、混合 Edit 组闭包和连续多次转移仍需补专项；旧文件中未记录的来源不能伪造。重复搬移产生的空列表整理、原性能/焦点/分析/长源/旧读者、实体录音与听评、Windows、发行等缺口继续保留。此增量不代表完整 P1/P3 或产品完成。

## Warp 准备失败的有界恢复

L1 只在停止状态、源媒体和映射仍有效且前一原生作业已退出时，为每个活动 Clip/处理 hash 允许一次原生缓存恢复；没有真实可读缓存仍返回 preparing/failed，不能播放或导出。第二次失败持续显示失败，不因界面轮询无限重试。预算是运行时状态，不写入工程或撤销历史，Edit 生命周期和实际处理 hash 改变后重置，已离开的片段会清理。代码 ElasticCommands.cpp；真实 OS 写盘限制的永久失败测试见 WarpTests.cpp。此次捕获了两个 Comp 片段的实际失败、无缓存、有效原媒体/映射；首作业失败的具体调用链仍未证明，不把恢复成功写成根因已解决。
