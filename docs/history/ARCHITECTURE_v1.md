# Architecture and decisions

## Iteration17: control-thread track groups and selection (current)

Schema7 stores stable-ID `track_groups` and boolean `groups_suspended`. Each group has literal name, type edit/mix/edit_mix, enabled, distinct existing track IDs and only implemented links volume/pan/mute/record/monitor. Edit members are current audio tracks; capture links require audio tracks; Master has no pan/mute/capture. Metadata admission estimates512 bytes/member across groups,64MiB total; target plans estimate4096 bytes/target,64MiB across operations. These are conservative admission estimates, not measured heap limits. NRT membership resolution has a5s deadline; no group/selection JSON traversal, locks, IO or allocation enters the audio callback.

The first enabled Mix group in displayed order containing the anchor and linking the attribute wins; conflicting groups do not silently union. Main gain/pan use differences from retained intended values, clamping actual fields to[-120,24]dB/[-1,1]. Optional track `group_values` retain finite intended values up to±1048576; consistency with clamped actual fields is validated. Moving back restores offsets. Individual/suspended edits reset the anchor's retained value. The renderer uses actual fields only. Mute/record/monitor absolute links do not alter output assignment, insert membership or input indices.

Edit resolution closes connected enabled Edit membership and collects active clips intersecting explicit selected-clip spans. It does not expand spans recursively through arbitrary long members. Batch operations mutate whole resolved clips; every explicit/expanded target must satisfy the operation or the entire local plan rejects. Full region/range editing and batch clipboard remain gaps. Linked Comp timing is mandatory regardless of general-group suspension: respect-move includes every linked piece; other structural edits require explicit detach/independent copy. Detach retains every clip, source map, envelope and historical comp_origin. Remapped trims materialize inherited edge factors and translate all endpoints with source-offset delta, preserving retained PCM; immutable Source/Take bounds are validated before commit.

GUI selection is stable-ID presentation state, pruned after project changes. GUI gestures, group staging and source menus pin identity/revision. Inline lanes read real inactive media and never enter playback implicitly; source audition/copy uses select_playlist/copy_range_to_playlist. Grouped timing operations stop transport until seamless live adoption is qualified. Native callbacks/event geometry are not mouse, listening or install evidence. Fixed Release128/256/512×4 target-plan/Undo budgets are in evidence/edit-groups/budget-declared.json; they measure NRT command latency, not stable playback capacity.


Iteration16 current model is **schema6**. Migration1–5 preserves legacy clips, plugin states and canonical transaction lineage, adding empty `comp_sets`; gain envelopes are optional. Saving uses existing checksum/stage/backup/journal mechanisms. Older schema5 binaries reject6 rather than silently losing envelopes. Linked CompSet IDs and member Playlist references are stable and globally validated; result timing hashes, shared ranges and all-or-none active selection protect against independent retiming. Original/target Playlists are separate. Sources are chosen by explicit Playlist/Clip IDs for every member/range; no inference by track name, numbering or guessed take quality.

Clip gain is the product of legacy edge fades and prepared bounded clip-local ramps. Slicing materializes inherited linear factors and shifts signed integer endpoints/source offsets; it does not render or alter original media. Inclusive transition endpoints are `[cut-floor(F/2), cut+ceil(F/2)-1]`, F=0 or >=2. Equal-gain pairs sum to1; equal-power uses sin/cos and may boost correlated audio. Adjacent core ranges get centered handles, gaps get no inferred transition; insufficient actual source-clip handles or triple transition windows fail. Up to64 envelope factors/clip,64 MiB compiled envelope array storage/graph and a conservative64 MiB/4096bytes-per-member-segment linked plan are predeclared. Resource overflow throws before media/SDK preparation; no dropped clips. Only bounded prepared arithmetic/libm enters shared RT/offline DSP; JSON, allocation, destruction and graph construction remain NRT. Fixed legacy numerical paths remain unchanged for old sessions.

`create_linked_comp` creates inactive members in one common transaction, with canonical IDs/origin/revision. `select_comp_set` and selection of a member Playlist atomically switch all members; restore requires all members still selected and all prior Playlists writable. Switching away restores the old group first. `move_comp_set` changes all project positions equally and updates timing signatures while leaving source offsets/envelopes untouched. GUI/AI stop transport before selecting/restoring/moving. Independent timing/capture edits of linked candidates are refused; copy/duplicate to an independent Playlist for those operations. This limited explicit Comp group does not constitute general edit/mix/VCA groups, arbitrary curves, grouped recording, seamless live switching, real multi-input phase alignment or time-stretch qualification. AI permission/version/capture pins/Undo remain shared. Native staging also pins source revision, including across intervening edits.

## Iteration 14: prepared loop clock and continuous media

Schema5 permits an optional `recording={mode,begin,end}` extension; absent preserves original normal behavior. `recordSettings` validates mode and bounded nonnegative integer sample coordinates. Continuous input/disk counters never wrap. Recording presentation counters describe acquisition/timeline samples rather than subtracting output processing delay. Runtime faults still fail capture and preserve partial files.

## ADR-002: ownership and realtime safety

Domain state is owned by `Commands` and serialized with a non-realtime mutex. GUI and AI publish validated snapshots, never mutate realtime graphs. A preparation worker compiles source/track/clip topology and coefficient targets, validates hashes on first source open, and checks unchanged file identity on reuse. Parameter-only changes reuse the raw PCM cache without reading/hashing an entire file again. A single atomic latest-wins mailbox transfers graph ownership to the callback. The callback retires obsolete graphs through a bounded 128-slot SPSC pointer queue; the preparation worker destroys them. No callback deletion or final shared-pointer release occurs. Transport epoch and state remain one atomic token, so seeks/stops reject stale work.

One disk worker decodes immutable **raw source PCM**, in 4,096-frame pages with up to two channels. The callback pins pages using bounded CAS operations; the writer can replace only an unpinned page. Each source has a bounded 16-slot multi-producer request mailbox (callback and preparer), LRU page selection and 8,192-frame source lookahead. The cache defaults to at least 16 pages per source, growing to four pages per distinct source-to-session offset. Default cache memory limit is 1 GiB through `EngineConfig`; exhaustion fails the new graph explicitly and retains the previous playing graph. The registry contains weak owners and reclaims expired entries off-thread. Changed/deleted media is detected by a background identity check (size/time and POSIX inode/change time); a faulted source requires explicit graph recovery and hash validation. Windows identity checking and actual IO still require Windows verification.

In device callbacks, DSP operates in chunks of up to 256 frames. It pins all required pages before advancing ramps, computes float64 track/clip gain, mono constant-power or stereo-balance pan, linear clip fades and channel sums, then writes float32. Gain/pan/mute target changes inherit actual previous ramp values and settle over 5 ms (240 frames at 48k); a split child inherits a matching parent ramp through a precompiled continuity index. No JSON, IO, GUI, inference, mutex, allocation or object reclamation occurs in this path. A missing page, invalid decoded sample or mix overflow fails playback visibly instead of advancing with fabricated silence. Priming waits for source availability. Prepared edits activate at callback boundaries; transport reaches the current active graph's actual content end, with no stale queued EOF packet. Updating the end before it is reached keeps playback going. Large topology adoption/prefetch budgets and all professional transport modes still need qualification.

The separate capture queue is now 128 × 512 × distinct configured input channels, allocated before callback publication within a configured 256 MiB memory budget. A mono/stereo route per armed track references the compact union of required enabled physical inputs; shared inputs are copied once and dispatched by the disk worker to separate files. There is no eight-channel production cap. Queue overflow/input faults stop capture and retain partial files/manifest. Callback timing, source-cache/queue bytes, applied request/revision/sample, host timestamp, publication-to-PCM time, ramp boundary, gaps and driver XRUNs are recorded separately. Known-input tests verify production mapping/writing and monitoring. Actual built-in microphone CLI capture/private aggregate/growth/reopen/export are now verified for two logical tracks sharing one input; multi-input interfaces, RTT/timestamp compensation, Punch, listening and endurance remain unexecuted.

**SDK boundary audit and replacement:** `evidence/realtime-wrapper-audit.json` preserves the pinned JUCE manager/CoreAudio callback locks, potential resize and callback-side stop call. macOS production open/configure/GUI/capture now use a direct `AudioDeviceCreateIOProcID` backend and bypass both wrappers. JUCE remains the UI/codec/metadata abstraction; its manager is retained for test-only device metadata and the unqualified Windows path. `CoreAudioBlock` preallocates planar float32 scratch/maps, validates HAL layout and independent sample clocks, deinterleaves selected inputs, calls the existing engine directly and interleaves only selected outputs. Source DSP/graph/capture code is retained. Full application IOProc timing is separate from the nested engine timer and excludes driver/kernel scheduling and the tiny C trampoline. The executed audit intercepts named common libc/HAL APIs; it is not a proof of all possible OS/plugin internals. The actual one-microphone/private-aggregate CLI gate passes; physical multi-input, clock drift, actual device faults, Windows and endurance remain gates.

Float64 applies to gain/pan/fade multiplication, routing/accumulation and the implemented limiter. Files retain their actual PCM format. The callback receives float32 from the device API. No third-party plugin precision claim is made. Source/session sample rates must currently match; unsupported rates/channel layouts are explicit failures rather than silent conversion/downmix.

## ADR-005: capture clock, lifetime and external-file commit

Tracks persist record arm, ordered physical input indices and off/input/auto mode. Input mode always monitors and suppresses clip playback. Auto monitors an armed track while stopped or recording, suppressing that track's playback while recording; unarmed/playback tracks play normally. Monitoring uses track gain/pan/mute and the float64 mix; captured PCM is dry, before those controls. Unavailable/non-finite monitor input is indicated and silenced. These initial rules are explicit, not a claim of full Pro Tools monitoring/PDC behavior. Mode changes need further dezippering/listening qualification.

Commands creates a lease that pins captured IDs/input/arm/lock while allowing compatible mix/edit transactions. Preparation snapshots actual enabled device indices into callback slots and creates all writers/queues outside RT. A capture job owns one worker; the callback sees only a raw pointer. Publication arms a specific transport epoch after the job is ready; an earlier callback cannot record pre-start samples. Timeline and all capture routes share one counter and continue beyond existing clip EOF. Device/rate/epoch faults surface as failure even when no following callback arrives. Stop clears the raw pointer, waits up to 2 s for the callback hazard flag outside RT, stops transport before file verification and reclaims only after quiescence. A timed-out callback keeps the owned job. OS disk-call blocking/finalizer cancellation still needs a bounded recovery policy; the worker join is not claimed to have a disk-stall deadline.

The disk worker consumes contiguous packets, writes each routed BWF float32 file and flushes headers/data every 250 ms of captured audio. It preserves raw partial files on any failure; a checksum manifest records provenance, paths and status. At stop, decoded format/frame counts/BWF time references/hashes must agree across all routes. Each finalized file is fsynced and published with an atomic no-replace hard link; all-file preflight happens first, but a later race can still produce partial publication, which remains a failed receipt. Session attachment is a separate one-transaction immutable import; Undo retains recordings. Stable capture-derived IDs/key make retries/restart idempotent, including after Undo. Successful unattached manifests can be reattached; repairing failed/interrupted partial files remains unfinished.

BWF placement currently equals the requested session sample position plus a shared capture count. Provenance records driver input/output latency, host time when supplied, device/backend, session revision/lease/capture ID and an explicit uncalibrated zero placement offset. macOS now supplies HAL input acquisition host time and keeps output presentation sample/host time separate. Sample-time gaps or invalid selected layouts fail the backend/capture rather than silently continuing a contiguous file. Physical input synchronization and placement still require loopback calibration; driver latency is not RTT. The unqualified Windows JUCE path has separate timestamp validation requirements.

## ADR-006: native CoreAudio boundary and qualified audit scope

`NativeDevice.h` defines NRT device setup shared by the GUI and CLI: stable actual input/output UIDs, physical input mask, ordered mono/stereo output ports, session sample rate, device buffer and a 64 MiB **scratch** budget. Empty UIDs resolve system defaults without changing those defaults. Preparation queries actual stream/channel/rate/buffer capabilities, checks indices before configuration, requires matching-rate native-endian float32 virtual PCM, and caches metadata/clock conversion. File PCM depth, internal float64 mix, HAL float32 virtual buffers and actual physical format remain separate facts. Unsupported formats fail explicitly. HAL IOProc stream usage is set and read back outside RT; unselected streams can have null mData and are never mistaken for selected input.

The C IOProc calls `CoreAudioBlock` directly; no AudioDeviceManager/CoreAudioInternal callback is invoked. Preallocated storage covers the reported maximum buffer range. Callback work is bounded by that prepared capacity/selected channels. Layout/selected-null/missing-sample-time/discontinuity faults silence supplied outputs, latch a numeric reason and notify a 1 ms polling NRT control worker. Property listeners only update atomics; one lifetime hazard covers the entire listener invocation and at most 32 addresses. Device query/set/start/stop/destroy, JSON, errors and thread joins occur NRT. Detachment clears the enabled/callback atomics and waits for all in-flight invocations before releasing the engine owner. A breached 2 s application budget latches fault 5 and `callback_owner_wait_timed_out`; NRT detachment continues waiting to protect an already-loaded engine pointer. Retaining only its buffers would not protect that owner. HAL-05 exercises this safety rule with a stalled test-only callback. Successful unregister plus quiescence permits storage reclamation. Failed/uncertain unregister retains detached callback storage for process lifetime **after owner quiescence**, charges the budget and prevents further over-budget opens; future invocations cannot access an AudioEngine. No exception-path owner allocation is required. OS AudioDeviceStop/joins and the fail-safe NRT timeout wait still lack bounded process-supervised recovery; this remains a release blocker, not a passed driver-stall test.

NRT registration covers device stream-list/configuration, alive/rate/buffer/abnormal-stop and each prepared stream's virtual/physical format. Stream-list notifications can invalidate stream IDs; any such notification fails the prepared backend and stops it NRT rather than interpreting a stale layout/format. Unregister uses the exact registered object/address pair. Known notification fixtures pass; actual hot format/stream changes remain unexecuted. Capture provenance snapshots the selected input UID, exposed channel coordinate, actual stream usage/virtual format and input acquisition clock separately from output presentation.

Separate physical input/output devices create an application-owned **private** aggregate, output device first/main clock, selected input device second with drift compensation. Physical input indices are translated by the output device's input-channel count; the aggregate alone is destroyed at close. Existing aggregate topology is never altered/destroyed; system default-device selections remain unchanged. Requested rate/buffer settings apply to the selected devices. The actual built-in microphone/private aggregate CLI capture and cleanup pass; the observed stream starts at HAL element 7 while its exposed ordinal is 0. Stream usage therefore uses validated exposed buffer/stream boundaries and records both coordinate systems. Underlying HAL element gaps must never disable a selected exposed channel. ## ADR-007: actual stereo routing, processing latency and publication

`Routing.cpp` compiles stable audio/Aux/main-master nodes and output/send edges into a validated acyclic graph on the control worker. Buses own explicit input tracks; the main bus remains as a unity output stage when there is no explicit master. All references, processor fields, ownership and cycles are validated before commit. Unknown processing and multichannel layouts fail explicitly. An output route and any sends are separate objects: adding a send preserves the original output. Deleting an Aux with incoming references is rejected. Locked source/destination tracks and processors remain protected.

Realtime and offline paths both execute `RoutingMixer` in float64. Audio/Aux order is raw clip/input sum -> actual insert chain -> independent main/send panning -> track fader/mute for output and post sends. Pre sends bypass track fader/mute and use their own pan. Mono contributions use the existing constant-power law; stereo contributions use balance. Main master fader precedes its inserts and has no sends/pan/mute. NativeDAW currently supports a stereo main master only; Pro Tools' arbitrary bus/path masters, linked send-pan/preferences, dual stereo panners, sidechains and multichannel routing remain gaps.

The builtin linked discrete sample-peak limiter uses a real lookahead FIFO and bounded maximum tree, immediate gain reduction and finite release. It reports its actual delay (0..8192 frames), not a fabricated plugin latency. Mixed mono/stereo contributions use a conservative magnitude bound. It does not provide true-peak protection or a verified mastering/hearing claim. Post-insert fader boosts and later sums can exceed a pre-fader limiter's ceiling. Offline render rebuilds actual history from session start for discontiguous processed ranges, with cancellation at every fixed block; compensation preroll/drain is removed so the exported BWF range/timestamp and file sample zero retain their original project meaning.

DAG longest-path propagation determines every edge's compensation delay and the main output's algorithmic latency. The configured 256 MiB shared admission budget includes node scratch, limiter FIFOs/trees/tags and stereo compensation rings across concurrent graphs; metadata, source cache and capture queue have separate costs. Admission failure retains the prior graph. All allocation and disposal occur NRT. RT reset invalidates delay/tree history by counters/generation tags; matching stable-ID histories swap vector storage in constant time. There is no callback delay-buffer clear. The single preparer alone reads immutable active topology metadata and reclaims retired graphs; the callback updates that pointer before retirement. Immutable generation tokens provide a constant-time final adoption guard.

Coefficient edits preserve delay state and use the existing 5 ms ramps. A running structural/tap/processing-latency change is explicitly refused by the engine; the committed project diff remains visible with requested/applied revisions distinct. Stop and explicit republication apply it safely. Recording leases also pin topology and delay. Seamless latency transitions and a calibrated low-latency monitoring/PDC bypass are release gates. Normal monitoring currently passes through the full compensated graph; dry capture placement remains uncalibrated.

Revision activation is conservatively delayed until the new graph's complete algorithmic window has drained; ramp settlement includes that window. Earlier individual paths may change first. This is processed-PCM evidence, not DAC/round-trip measurement or proof that all acoustic effect history has become a new state. Processing-source position and delay-adjusted content presentation position are separate telemetry; the native playhead uses content position. Device/converter/acoustic delays remain separately reported, uncalibrated. Atomic route meters expose actual processed-block counts/revisions and sample peaks, never invented activity for prepared nodes.
