冻结缓存搬动后，原路径/哈希/插件和Clip保留，播放和导出明确拒绝。Cmd Ctrl Option R或轨头菜单「重定位冻结缓存…」选择实际WAV；L1要求原SHA256、48k双声道及帧数全部一致。事务只更新引用并保留重定位来源，不移动、复制或覆盖文件；Undo精确恢复旧引用（可能缺失），Redo恢复核验的路径。文件选择期间session/revision变化则拒绝。

Freeze复用Tracktion原生FreezePoint与缓存WaveNode。原Clip/MIDI和插件保留，已印刻前缀DSP从实时与离线图跳过；原源缺失时独立新引擎仍可读取核验的缓存。原地Bounce在同轨创建真实可编辑Wave Clip及独立Playlist，保留原Playlist和插件实例；printed_bypass说明DSP已经印刻，原生图不会重复处理。还原切回原Playlist和原生DSP，打印列表及后续编辑保留，还原本身可撤销。

印刻接收总线之后，上游轨道发往其他Aux/旁链的分支仍作为native sink参与图。它们不重复混入接收缓存；仍需供给其他路由的上游处理不会因冻结被省掉。发送Aux的依赖长度从真实路由图追踪，不能以没有自身Clip判为空轨；还原能够找到隐藏的原生AuxReturn。效果器中间tap发送与关联Comp整组印刻仍明确拒绝。
