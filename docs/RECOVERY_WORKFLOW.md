# 工程恢复副本

结论：开发版提供停止状态下的自动工程副本和人工确认恢复。它保存真实 Tracktion Edit，原工程文件和媒体不覆盖；不是录音期间的 WAL 或完整灾难恢复。

## 亲手试

1. 打开开发应用，导入音频，建立几条轨道或插入效果器。
2. 选择“文件 → 工程恢复副本…”，点击“立即保存恢复副本”。等实际写入回执出现，列表中会显示保存时间与工程版本。
3. 关闭面板，继续修改工程。再次打开面板，选择之前的副本，点击“查看恢复预览”。此时工程不变。
4. 点击“确认恢复为新会话”。程序核验选中的校验和，先写入当前工程的恢复副本，再切换工程。期间的人工修改会使恢复被拒绝。
5. 检查时间线、路由和参数，播放试听。用“另存工程”将恢复结果保存到新文件；列表也保留恢复前的工程副本，可以再次恢复它。

默认自动保存间隔 60 秒，可设为 10–600 秒或关闭，偏好会保存。播放、录音、参数手势、自动化写入、设备准备和未完成的原生插件状态捕获会延期保存；状态栏和面板显示延期或失败。自动模式只保存发生变化的工程。退出或崩溃前尚未到达保存间隔的修改可能没有副本。

## 数据与边界

- 默认目录为应用设置目录下的 `Recovery`（macOS 通常 `~/Library/NativeDAW-v2/Recovery`），面板显示实际路径。目录仅允许当前用户访问；已有不合格目录会明确失败，不静默改权限。
- 一个副本由独立 `.tracktionedit` 和 JSON manifest 构成。后台先完成新 XML 的原子写入和系统同步，再提交 manifest；manifest 是完成标记。只读出完整、匹配 SHA-256 与 revision 的 XML 后才允许切换。
- 音频媒体不复制；WaveAudioClip 的相对路径在副本中解析为原位置，原工程不改。缺失媒体和插件引用保留。第三方插件的私有外部素材和其他 SDK 媒体对象的相对路径不在本轮资格中。
- 本地确认恢复时立即把 MCP 网关和命令文件权限回到只读；取消或读取失败不自动恢复之前的写权限。切换成功后新建 session token、清空本轮 Undo/Redo 与执行回执、关闭输入监听。历史请求键只作 `recovery_requires_review` 核对依据。之后的普通人工编辑仍可撤销。
- 恢复前的当前状态必须成功备份；目标损坏、写盘失败、会话/revision 冲突或取消均不切换。取消阻止工程切换，已经完成的副本保留；不能承诺抢占正在执行的操作系统磁盘调用。
- 一次只运行一个后台 I/O 作业。单副本上限 64 MiB，目录最多 1024 份副本和 4 GiB，不静默删除旧副本。达到预算时关闭应用，再由用户明确移动旧副本到自己的归档目录。
- 只有工程状态恢复回执，不自动声称音频已验证。持久 Undo、活动录音缺口恢复、逐事务 WAL、磁盘满/电源故障全面资格、任意第三方插件捕获时限仍未完成。

## 实现与自动验证

L1：`src/v2/SessionRecovery.cpp`（捕获、版本检查、恢复控制）、`RecoveryStore.cpp`（后台校验与原子存储）、`EngineCommands.cpp`（同一 Edit 接管）。L5：`RecoveryPanel.h` / `Workspace.h`，不直接写 Edit。

测试编号 `M1-RECOVERY-01`：`tests/v2/SessionRecoveryTests.cpp`、`RecoveryWorkspaceTests.cpp`。固定 64 轨道工程含音频、MIDI、EQ、Aux 与自动化；验证对象恢复、144000 帧/48 kHz/24-bit/双声道实际渲染、解码 PCM 一致、原文件哈希、自动计时、损坏与孤立文件、真实 OS 写入失败、并发人工编辑、取消、相对媒体、历史请求标记和真实子进程 SIGKILL 后恢复。原生组件回调验证菜单、预览、确认、权限撤回与恢复后的新 Undo。

实施前预算：该固定工程 message-thread 捕获 <1 秒、普通后台作业 <5 秒、3 秒音频渲染 <10 秒；结果见 `docs/VERIFICATION.md` 和本地 `evidence/M1/summary.md`。不以这些自动测试代替物理点击、主观试听或完整 M1/M2 验收。
